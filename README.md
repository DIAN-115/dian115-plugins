# dian115-plugins

DIAN115 第三方插件仓库。根目录是可安装的正式包，插件源索引在 `plugin-market/v3/index.json`。

## 作为插件源添加

插件商店右侧支持一行一个索引地址，把下面这行粘进去即可（本机实测能列出插件）：

```
https://raw.githubusercontent.com/DIAN-115/dian115-plugins/main/plugin-market/v3/index.json
```

注意：索引里的包是经宿主编译 MCP 正式编译的 v4 包（`delivery: "protected-v4"`），从 URL / 市场安装走的就是这条路，不会再被「新正式发布必须通过编译 MCP；源码仅允许本机调试」拦住。正式包的开发者名称取签名绑定的 DIAN115 会员昵称，会覆盖插件清单里自填的作者。

## 插件

### 缺集自动订阅 · dian-missing-subscribe 1.0.6

读取宿主已有的缺集扫描结果，按多条规则逐季判定，自动创建或合并 DIAN115 聚合订阅。

**规则与动作**

- 规则从上到下匹配，每一季只用第一条命中的规则；可上下调顺序
- 筛选条件：Emby 实例、媒体库、连载中/已完结、只看最新季、最小/最大缺集数、缺集比例上限、至少已有几集、季号下限、首播年份区间、类型与排除类型、地区、片名包含/排除关键词、TMDB ID 白名单/黑名单
- 动作：自动订阅 / 忽略（没有审核队列，历史规则里的「进待审」一律按忽略处理）
- 订阅方式：`fixed` 只补当前缺的集，`follow` 补完后继续跟新集；可指定观察期小时数、这条规则的单轮上限、资源来源

**触发与保护**

- 每小时一次（`interval_seconds: 3600`），另外宿主缺集扫描完成事件 `library_missing_scan` 会立即再跑一轮
- 独立任务「剧集删除同步」（`prune`，`interval_seconds: 600`）：每 10 分钟只核对一次「订阅对应的剧还在不在 Emby 里」，不读缺集报告、不建订阅。宿主的缺集扫描事件不会因为「删了一部剧」而触发，而跑一整轮又太重，所以删除剧集后最多等一个间隔就会自动收掉订阅，不用手动点「立即运行」。
- 自动运行默认关闭，页面上那个开关打开后才定时自动跑；手动「立即运行」不受限
- 提交前再向 Emby 查一次实时集号，减掉已入库的集，避免拿缓存结果建重复订阅
- 只动本插件创建的订阅：别人的订阅、洗版订阅一律不碰；自己的进行中订阅只能 PATCH 合并（直接 POST 会覆盖快照）
- 失败/过期订阅在冷却期（默认 7 天）后重建，冷却期内跳过
- 全局单轮上限（默认 20），加上每条规则自己的 `max_per_run`；用满后剩下的顺延到下一轮
- **剧集被删 → 同步删订阅**：每轮读一次 Emby 还留在库里的全部剧集 id，订阅那一季对应的剧集已经不在里面（整部剧被删、或整个媒体库被删），就把这条订阅删掉、从账本移除并在记录里留一条「已删订阅」；缺集报告里的旧结果也不会再拿去重建。分页只拿到一半（总数与实际条数对不上）或 Emby 读不到时不下结论。同一套判断也由 `prune` 任务每 10 分钟跑一次，只是不做订阅动作。可在运行设置里关掉。

**通知**

运行结束按设置推送摘要（渠道可选全部/Telegram/企业微信），不带回调按钮。

**页面**

总览（顶部「上次运行」状态条，带触发来源标签；下面三张统计卡各有一行小字副信息；一行自动运行开关；运行设置；底部「最近记录」列出最近 4 条）、规则（列表调序/启用/编辑，带 4 个模板）、订阅（进行中与已补齐两个视图，已补齐可清除记录）、记录（运行日志 + 已忽略恢复）。没有「审核」标签页，也没有「规则试运行」任务。

「上次运行」状态条把时间与「检查 N 季 / 订阅 / 删订阅 / 顺延 / 失败 / stopped」标签分开显示，最左边是这一轮的触发来源（定时 / 手动 / 库扫描后）。「删订阅」是这一轮的次数，不是累计（累计看记录页里「已删订阅」的行数）。

三张统计卡下面的小字分别是：「近 7 天新增 N」、「上次补齐 月日 时分」、「共 N 条规则」（有停用时显示「共 N 条 · 停用 X」），都是纯展示，不改任何数据。

「订阅进行中」按账本判定，新建或合并成功的订阅在同一轮收尾时不会被误判成已过期；后台定时/事件跑完，页面每 12 秒同步一次订阅池与账本，数据变了才重绘（弹窗编辑中与本地任务运行时不动）。

账本键是 `实例:TMDB:季`，一定带着订阅池里的 `intent_id` 才认得回那条订阅（1.0.6 起：写入改成整块替换，新建后宿主没回 id 就回池补查，保存后回读发现某条只存成空对象就补写一次；对账时拿运行记录里建过的季作凭据，把丢了 id 的账本认回来；页面统计与「订阅」页也同时认 `intent_id` 与「记录里我建过 + 池里还在」，不会再出现新加的订阅不进「订阅进行中」）。

**界面（Liquid Glass）**

- 卡片 / 胶囊 / 列表行共用一套半透明玻璃底（`backdrop-filter: blur(24px) saturate(185%)`）、上缘斜向高光、四周 1px 内高光边、下投影
- Chromium 下叠一层 SVG 位移滤镜做真折射（`url(#ms-refraction)`）；弹窗不参与，改用近乎不透明的面板保证可读
- 彩色只留在卡片自己的玻璃层（`--sheen-*` 双层渐变），卡片之间的间隙交还宿主底色 `--app-bg`
- 环境光、弹窗遮罩、提示都收在内容区（`.ms-ambient` / `.ms-scrim` 用 `absolute;inset:0`），不铺满整个宿主窗口
- 标签栏是占满整行的胶囊分段控件（46px 高、15.5px 字），选中态用实心 accent 渐变 + 内高光
- 原生下拉显式声明 `color-scheme` 并给 `option` 配色，深色下不会出现白底浅字
- 弹窗遮罩用 `fixed` + 安全区内边距 + 可滚动，面板再高也不会被顶出屏幕
- 媒体查询兜住窄面板（≤540px）：统计卡自动等分一行、列表行允许换行、弹窗改 86vh；544 这类宿主面板宽度下运行设置仍保持两列，两个勾选项单独一行，整页不会被拉成一条长卷
- 样式全部限定在 `.ms` 作用域，不污染宿主

#### 安装

DIAN115 插件中心 → 第三方插件，上传仓库根目录的 `dian-missing-subscribe-1.0.6.dian115p`。这个包是宿主编译 MCP 输出的 `protected-v4` 正式包（内部只有 `release.json` / `runtime.bin` / `review.bin`），不是可读源码 zip。

在已装旧版的宿主上，插件中心的「更新」会原地升级（实例 id 不变，配置、规则、账本、记录都保留）。装好后若没在侧边栏看到，到插件管理「权限与显示」里打开「显示在侧边栏」。

#### 关于安装检查的 risk

宿主静态分析会把 `filter` / `sort` / `trim` / `padStart` 这类对动态值的方法调用归入「执行动态代码」，所以报告 `risk` 常显示 `unknown`。插件里没有 `eval`、没有 `new Function`、不碰凭据，这是启发式误判。

## 正式包

仓库根目录的 `.dian115p` 由宿主编译 MCP 生成（`protected-v4`，内部只有 `release.json` / `runtime.bin` / `review.bin`），本机压不出来，也不能用源码包上架。改动后提高版本号、重新编译、再「更新」安装即可；宿主不允许安装后再改代码。

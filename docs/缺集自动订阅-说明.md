# 缺集自动订阅（DIAN115 插件）

读取宿主已有的 Emby 缺集扫描结果，按规则逐季判定，自动在 DIAN115 创建「缺集补全」聚合订阅。界面为 Liquid Glass 玻璃质感。

## 文件

| 文件 | 说明 |
| --- | --- |
| `dian-missing-subscribe-1.0.6.dian115p` | 宿主编译 MCP 输出的 `protected-v4` 正式包，用于「插件中心 → 第三方插件」安装，也可作为商店来源包 |

## 安装

1. 打开 DIAN115 → 插件中心 → 第三方插件，选择 `dian-missing-subscribe-1.0.6.dian115p`。
2. 确认作者（正式包的作者是签名绑定的会员昵称，不是源码里自填的名字）与检测到的操作后安装。
3. 若没在侧边栏看到，到插件管理「权限与显示」里打开「显示在侧边栏」。
4. 打开插件页面，先建规则，再决定是否打开「自动运行」。

已装旧版的宿主选「更新」即可原地升级，实例 id 不变，配置、规则、账本、记录都会保留。

安装后代码不能再修改；改动需提高 `plugin.json` 的 `version`，重新经编译 MCP 出包后再「更新」安装。

## 规则

规则从上到下匹配，每一季只用第一条命中的规则，可上下调顺序。

- 筛选：Emby 实例、媒体库、连载中/已完结、只看最新季、最小/最大缺集数、缺集比例上限、至少已有几集、季号下限、首播年份区间、类型与排除类型、地区、片名包含/排除关键词、TMDB ID 白名单/黑名单
- 动作：**自动订阅** 或 **忽略**（没有审核队列；历史规则里的「进待审」在页面和后台都按忽略处理）
- 订阅方式：`fixed` 只补当前缺的集，`follow` 补完后继续跟新集；可设观察期小时数、这条规则的单轮上限、资源来源

## 运行

- 每小时一次，另外宿主缺集扫描完成（`library_missing_scan`）后会立即再跑一轮
- 另有独立任务「剧集删除同步」（每 10 分钟）：只核对订阅对应的剧还在不在 Emby 里，不读缺集报告、不建订阅。删掉一部剧后不用手动点「立即运行」，最多等 10 分钟就会自动收掉它的订阅
- 自动运行默认关闭；页面上的「立即运行」不受此限
- 提交前用 Emby 实时集号再减一次已入库的集，避免拿缓存结果建重复订阅
- 只动本插件创建的订阅；别人的订阅、洗版订阅不碰，自己的进行中订阅只能 PATCH 合并
- 失败/过期订阅在冷却期（默认 7 天）后重建
- 全局单轮上限（默认 20）加每条规则自己的上限，用满后剩下的顺延到下一轮
- **剧集被删后同步删订阅**：每轮读一次 Emby 还留着哪些剧集，订阅那一季的剧已经不在里面（整部剧被删，或整个媒体库被删），就删掉这条订阅、从账本移除，并在记录里留一条「已删订阅」；旧缺集结果也不会再拿去重建。Emby 读不到、或分页只拿到一半时不下结论
- 运行结束按设置推送摘要（全部 / Telegram / 企业微信），不再带「批准 / 忽略」按钮

## 页面

- 总览：最上面一条「上次运行」状态条（触发来源 + 时间 + 检查 N 季 / 订阅 / 删订阅 / 顺延 / 失败 胶囊），下面三张统计卡（订阅进行中 / 已补齐 / 启用规则，各带一行小字副信息）、一行自动运行开关、运行设置，底部还有一块「最近记录」列出最近 4 条，右上可跳记录页
- 规则：列表调序、启用、编辑，带 4 个模板
- 订阅：进行中、已补齐两个视图，已补齐可清除记录
- 记录：运行日志 + 已忽略项一键恢复

「删订阅」是这一轮的次数，不是累计；累计看记录页里「已删订阅」的行数。

## 账本与「订阅进行中」怎么算

账本（storage `ledger`）的键是 `实例:TMDB:季`，每条记着 `intent_id`、`outcome`、`last_action_at` 等；`outcome` 不是 `landed` / `failed` / `expired` 且能对得上订阅池的那一条，就算「订阅进行中」。

1.0.6 修过一处：「新建的订阅没被计进订阅进行中」。原因是宿主偶尔把账本里新加的那一条只落成一个空对象，`intent_id` 一丢，页面就把它当成别人的订阅排除了（订阅池里其实有那一条）。现在的做法：

- 写入改成整块替换 `state.ledger[key] = {...}`，不再原地改对象
- 新建/合并后宿主没回 id，就回订阅池按「季」补查一次
- `saveState()` 后回读账本，发现某条只存成空壳就补写一次，补不回来则在任务日志里写一条
- 对账拿运行记录里 `subscribed` / `merged` 的季作凭据，把丢了 `intent_id` 的账本认回来，不再永久当作「别人的订阅」
- 页面统计与「订阅」页同时认 `intent_id` 与「记录里我建过 + 池里还在」，口径不再靠单个字段

## 设置项（storage `config`）

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `auto_enabled` | false | 自动运行总开关；关闭后定时与事件触发都直接跳过，手动运行仍可 |
| `max_per_run` | 20 | 单轮最多新建/合并多少条订阅 |
| `cooldown_days` | 7 | 失败订阅的重试冷却期 |
| `throttle_ms` | 1500 | 每条订阅之间的间隔，0 表示不等 |
| `notify_enabled` | true | 是否发结果通知 |
| `notify_channel` | all | `all` / `telegram` / `wecom` |
| `drop_on_series_removed` | true | 某部剧从媒体库删除后是否同步删掉它的订阅（完整任务与每 10 分钟的清理任务都按它判断） |

兼容说明：旧键 `drop_on_library_removed` 仍与 `drop_on_series_removed` 一起判断，任一为 `false` 就不做同步删除；页面上的「剧集被删就删订阅」勾选框会同时写这两个键。

规则存在 storage `rules`（数组）；账本、忽略名单、运行记录分别是 `ledger` / `ignored` / `history`。`review` / `preview` 已不再读写，老数据留着不影响运行。

插件只在宿主内部读写 Emby、TMDB 与订阅池数据，不访问外部站点，不读写任何账号、密码或 Token。

## 关于 risk 显示 unknown

宿主静态分析会把 `filter` / `sort` / `trim` / `padStart` 这类对动态值的方法调用归入「执行动态代码」，所以报告 `risk` 常显示 `unknown`。源码里没有 `eval`、没有 `new Function`、不碰凭据，属于启发式误判。
